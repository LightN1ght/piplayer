# Первый запуск публичного образа

Публичный образ не содержит общего действующего административного ключа или пароля SFTP. До настройки Wi-Fi точка доступа не запускается, входящие учётные данные заблокированы. Каждый владелец задаёт свои данные через загрузочный раздел носителя.

1. Создайте индивидуальный ключ Ed25519 на своём компьютере, если у вас его ещё нет:

   ```bash
   ssh-keygen -t ed25519 -f piplayer-admin
   ```

   Для Windows команда доступна при установленном OpenSSH Client. Файл `piplayer-admin` — приватный ключ, его нельзя передавать. Содержимое `piplayer-admin.pub` — открытый ключ для следующего шага.
2. Запишите публичный `.img` на microSD или USB-накопитель. Запись стирает выбранный носитель. После записи извлеките и снова подключите его; откройте видимый Windows/Linux загрузочный раздел FAT. USB-загрузка зависит от настроек загрузки Pi.
3. В корне этого раздела создайте **обычный текстовый файл** `piplayer-setup.txt` в ASCII или UTF-8 без BOM. Заполните свои значения вместо строк в угловых скобках:

   ```text
   SSID=<имя сети>
   WIFI_PASSWORD=<свой пароль Wi-Fi>
   COUNTRY=RU
   CHANNEL=6
   SFTP_PASSWORD=<свой пароль SFTP>
   ADMIN_KEY=<полная строка из piplayer-admin.pub>
   ```

   Не оставляйте угловые скобки. SSID: 1–32 символа, английские буквы, цифры, пробел, `_`, `.`, `-`. Пароли: 8–63 символа из английских букв, цифр и `_.@+!-`, без пробелов. `COUNTRY` — две заглавные буквы; выберите страну использования. Канал — от 1 до 11. `ADMIN_KEY` должен начинаться с `ssh-ed25519 ` и содержать открытый ключ целиком; комментарий допускается. Не используйте старые личные пароли: текстовый файл временно доступен с носителя, а удаление на FAT не гарантирует его безопасного стирания.
4. Безопасно извлеките носитель и включите Pi. При корректной настройке она сохранит свои данные, удалит файл настройки с загрузочного раздела и поднимет точку доступа. Если файл отсутствует или содержит ошибку, настройка останется незавершённой; исправьте файл на компьютере и перезагрузите Pi. Наличие сети проверяется на физической плате, не в QEMU.
5. Подключитесь к указанной сети и откройте `http://192.168.50.1:8080/`. Для SFTP используйте пользователя `player`, заданный `SFTP_PASSWORD`, адрес `192.168.50.1` и порт 22. Загружайте видео как `/data/incoming/video.part` и переименовывайте в `/data/incoming/video.ready.mp4` после завершения передачи.
6. Административный SSH: `ssh -i piplayer-admin root@192.168.50.1`. Можно также использовать тот же ключ для входа `player` и SFTP. Для внешней программы адрес HLS — `http://192.168.50.1:8080/stream.m3u8`.

Чтобы сменить параметры после настройки, используйте [CONFIGURATION](CONFIGURATION.md). Не публикуйте свой файл настройки, приватный ключ или пароли.

Публичный образ можно собрать через `scripts/build.sh --public --configure`. Обычный `scripts/build.sh` создаёт персональную сборку по `credentials.json` и не требует этого шага. Обе команды требуют Linux и зависимости из [README](../README.md).
