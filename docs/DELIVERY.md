# PiPlayer: комплект для передачи

Основной сценарий проверен 5–6 ноября 2026 на Raspberry Pi 4 Model B Rev 1.2 с 4 GB RAM. Использовалась USB-флешка; старую microSD и EEPROM не меняли.

## Файлы в dist

| Файл | Назначение |
| --- | --- |
| `piplayer-rpi4.img.xz` | Сжатый образ, 29114608 байт; распаковать перед прямой записью либо выбрать в программе, поддерживающей xz |
| `piplayer-rpi4.img` | Тот же raw-образ, 470810624 байта; записывается на весь носитель |
| `SHA256SUMS` | Контрольные суммы обоих образов |
| `QUICKSTART.md` | Запуск, SFTP-загрузка, формат видео, настройки AP |
| `VALIDATION.md` | Результаты проверок и их ограничения |
| `demo.mp4` | Тестовый H.264/AAC-ролик со звуком |
| `piplayer-source.tar.gz` | Исходники проекта и документация без приватных файлов |
| `upstream-sources-and-licenses.tar` | Материалы зависимостей; ограничения комплекта описаны в THIRD_PARTY.md исходников; на карту не записывается |
| `SOURCE_SHA256SUMS` | Контрольные суммы архивов исходников |

`credentials.json` и `admin_ed25519` передавать владельцу устройства приватно: это пароль пользователя/Wi-Fi и административный ключ. В публичный архив их не добавлять.

## Подтверждённый сценарий

- Реальный firmware boot с финального raw, Ethernet DHCP, SSH/SFTP, загрузка `.part` с переименованием в `.ready.mp4`.
- Общий бесконечный HLS с H.264/AAC, слышимый звук и fullscreen в браузере пользователя.
- Wi-Fi AP PiPlayer, подключение телефона, DHCP и просмотр без Интернета.
- Отклонение повреждённого файла без остановки прежнего видео, восстановление после завершения FFmpeg, reboot с сохранением ролика и SSH host key.
- Автоматический прогон на плате: 901 секунда, 180 проверок HTTP/HLS, без остановки или перезапуска потока. Браузер непрерывно все 15 минут отдельно не наблюдался.
- Холодный старт без Ethernet подтверждён пользователем. Кабель подключён позднее: в журнале link up на 88-й секунде, DHCP/SSH/HTTP восстановились, ролик и AP работают.

## Условия использования

MP4: H.264 8 bit yuv420p, AAC либо без звука. Другие форматы заранее подготовить `scripts/prepare-video.sh` на компьютере. На Pi произвольное видео не транскодируется.

AP: `192.168.50.1`, HTTP `:8080`, SSH/SFTP `:22`. Через Ethernet использовать адрес DHCP роутера. Автоматический звук требует нажатия кнопки в браузере.

Настройки находятся в отдельном файле **на устройстве**: `/etc/player/player.conf`. SSID, пароль, страна и канал меняются через административный SSH, затем `/etc/init.d/S45accesspoint restart`. Файл имеет shell-синтаксис: сохранять корректные кавычки. Данные доступа в локальном credentials.json после ручного изменения автоматически не обновляются.

## Границы проверки

Raw занимает 449 MiB и проверен против предела 480000000 байт. Физическая microSD номиналом 512 MB не использовалась: аппаратная проверка шла с USB32GB, с теми же фиксированными разделами. После demo доступно около 248 MiB; при замене одновременно нужны место под старый и новый ролик. Раздел автоматически на весь большой носитель не расширяется.

SFTP проверен через Ethernet и вручную пользователем через Wi-Fi с Android: собственный ролик загружен, опубликован переименованием и воспроизводится со звуком. Одновременный просмотр на ноутбуке и телефоне60с со звуком без остановок подтверждён пользователем. Максимальная нагрузка несколькими клиентами и произвольные пользовательские ролики отдельно не измерялись. Раздельные режимы eth0/eth1 исключены из обязательного объёма по согласованному ТЗ.

Для передачи достаточно одного из двух образов, SHA256SUMS, инструкции и приватного комплекта доступа. Исходники и материалы зависимостей приложены отдельно. Текущий образ на плате дополнительно менять для сдачи не требуется; параметры организатора при необходимости задаются конфигурацией.
