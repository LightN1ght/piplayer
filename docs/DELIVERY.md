# PiPlayer: комплект для передачи

## Версия комплекта

Текущий raw собран с optional Ethernet и постоянным `/stream.m3u8`: **470 810 624 байта**, SHA256 `a111a19f1347ed81cf75625a5b08aae4ef1b4f7d01e9cb9833362152505e00cb`.

XZ: **29 121 940 байт**, SHA256 `62dbe6c74f7167cbbb10bcedf006894b81a93d6a6825cc2b5fbd1a3377a94001`.

Чистая ARM VM прошла базовый и двухсетевой smoke с reboot, прямой HLS-клиент со сменой ролика и mpv-декодирование H.264/AAC. Хостовые 17 тестов PASS. Физическая Pi пока остаётся на прежнем базовом raw; для fixed HLS устройство необходимо обновить и отдельно проверить. Программа организатора пока неизвестна. Полные результаты: [VALIDATION](VALIDATION.md).

Основной сценарий базового образа проверен 5–6 ноября 2026 на Raspberry Pi 4 Model B Rev 1.2 с 4 GB RAM. Использовалась USB-флешка; старую microSD и EEPROM не меняли.

Исходники и документация опубликованы в приватном [LightN1ght/piplayer](https://github.com/LightN1ght/piplayer), ветка main. Готовые образы и приватные данные доступа остаются отдельным комплектом.

## Подтверждённый сценарий базового образа

- Реальный firmware boot с базового raw `8f4d68e8…`, Ethernet DHCP, SSH/SFTP, загрузка `.part` с переименованием в `.ready.mp4`.
- Общий бесконечный HLS с H.264/AAC, слышимый звук и fullscreen в браузере пользователя.
- Wi-Fi AP PiPlayer, подключение телефона, DHCP и просмотр без Интернета.
- Отклонение повреждённого файла без остановки прежнего видео, восстановление после завершения FFmpeg, reboot с сохранением ролика и SSH host key.
- Автоматический прогон на плате: 901 секунда, 180 проверок HTTP/HLS, без остановки или перезапуска потока. Браузер непрерывно все 15 минут отдельно не наблюдался.
- Холодный старт без Ethernet подтверждён пользователем. Кабель подключён позднее: в журнале link up на 88-й секунде, DHCP/SSH/HTTP восстановились, ролик и AP работают.

## Условия использования

MP4: H.264 8 bit yuv420p, AAC либо без звука. Другие форматы заранее подготовить `scripts/prepare-video.sh` на компьютере. На Pi произвольное видео не транскодируется.

AP: `192.168.50.1`, HTTP `:8080`, SSH/SFTP `:22`. Через Ethernet использовать адрес DHCP роутера. Автоматический звук требует нажатия кнопки в браузере.

Настройки находятся в отдельном файле **на устройстве**: `/etc/player/player.conf`. SSID, пароль, страна и канал меняются через административный SSH, затем `/etc/init.d/S45accesspoint restart`. Файл имеет shell-синтаксис: сохранять корректные кавычки. Данные доступа в локальном credentials.json после ручного изменения автоматически не обновляются.

## Границы проверки

Raw занимает 449 MiB и проверен против предела 480000000 байт. Физическая microSD номиналом 512 MB не использовалась: аппаратная проверка шла с USB32GB, с теми же фиксированными разделами. После demo доступно около 248 MiB; при замене одновременно нужны место под старый и новый ролик. Раздел автоматически на весь большой носитель не расширяется.

SFTP проверен через Ethernet и вручную пользователем через Wi-Fi с Android: собственный ролик загружен, опубликован переименованием и воспроизводится со звуком. Одновременный просмотр на ноутбуке и телефоне 60 с со звуком без остановок подтверждён пользователем. Максимальная нагрузка несколькими клиентами и произвольные пользовательские ролики отдельно не измерялись. Режимы по destination-адресам добавлены отдельно как opt-in; они не входят в аппаратную приёмку базового raw.

Для передачи достаточно одного из двух образов, SHA256SUMS, инструкции и приватного комплекта доступа. Исходники и материалы зависимостей приложены отдельно. Для сдачи с постоянным HLS URL требуется обновить прежний образ на плате; параметры организатора при необходимости задаются конфигурацией.

## Перед обновлением устройства

Проверить SHA256 передаваемого raw и выбрать конкретный носитель. Прежняя аппаратная приёмка относится к базовому образу без `/stream.m3u8`; после обновления повторить HLS в требуемой внешней программе, звук, цикл, смену ролика, reboot и необходимые сетевые режимы. Не записывать образ на угаданный диск.

Браузер: `http://192.168.50.1:8080/`; внешняя программа: `http://192.168.50.1:8080/stream.m3u8`. Через Ethernet — DHCP-адрес Pi, тот же порт и путь. Вход MP4 H.264/yuv420p/AAC, GOP ≤4 секунды и ≤6 Мбит/с по пакетам; helper работает на хосте, Pi не транскодирует. Подробности: [HLS](HLS.md), [ETHERNET](ETHERNET.md).
