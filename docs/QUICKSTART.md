# PiPlayer: запуск и проверка

Актуальная версия и протоколы проверок: [CURRENT_STATE](CURRENT_STATE.md), [VALIDATION](VALIDATION.md). Аппаратная приёмка базового образа не переносится автоматически на обновлённый raw.

## Первый запуск и загрузка

Целевая плата — Raspberry Pi 4 Model B. Образ записывается целиком на носитель, не копируется как файл. Предел raw — 480 000 000 байт. Запись стирает выбранный носитель: внимательно проверьте его в Raspberry Pi Imager или Etcher. Физическая карта 512 MB отдельно не проверялась; аппаратный baseline запускался с USB.

1. Проверьте `SHA256SUMS` и запишите `piplayer-rpi4.img` на выбранный носитель. USB boot требует соответствующей поддержки уже настроенной Pi; проект не меняет EEPROM.
2. Включите питание. При первой загрузке генерируются SSH host keys.
3. Подключитесь к Wi-Fi по SSID и паролю из приватного `credentials.json`. Подключение без Интернета ожидаемо; подтвердите, что хотите остаться в этой сети.
4. Откройте `http://192.168.50.1:8080/`. Без видео страница предложит загрузить файл. Через Ethernet найдите DHCP-адрес `piplayer` в роутере и используйте тот же порт 8080.
5. По SFTP подключитесь к `192.168.50.1:22`, пользователь `player`, пароль из приватного комплекта.
6. Загрузите `/data/incoming/video.part`. После завершения передачи переименуйте его в `video.ready.mp4`; префикс имени может быть любым.
7. Сервис проверит файл и активирует его как `/data/media/current.mp4`. Нажмите «Смотреть со звуком» для звука и запроса fullscreen. При замене ролика страница переподключается автоматически.

Формат: MP4, H.264 8 bit yuv420p, AAC либо без звуковой дорожки. Рекомендуется подготовка на компьютере с FFmpeg/libx264:

```bash
scripts/prepare-video.sh original.mov ready.mp4
python3 scripts/upload.py ready.mp4 --host 192.168.50.1 --key dist/admin_ed25519
```

Helper задаёт ширину до 1280, 25 fps, видеобитрейт 2 Мбит/с, maxrate 3 Мбит/с, VBV 2 Мбит и GOP 2 секунды. На Pi транскодирования нет. Неподходящий файл остаётся в incoming с `.rejected`; прежнее видео продолжается. `.part` никогда не проигрываются: после неудачной передачи их можно удалить по SFTP. Не загружайте прямо в `media/current.mp4`.

## Внешняя HLS-программа

Браузер: `http://192.168.50.1:8080/`. Для новой версии внешний клиент открывает `http://192.168.50.1:8080/stream.m3u8`; через Ethernet замените адрес на DHCP-адрес Pi. URL не меняется при замене активного файла; служебный m3u8 не означает очередь роликов. После reboot клиенту без автореконнекта может понадобиться открыть тот же URL заново. Программа организатора неизвестна; совместимость ещё проверяется. См. [HLS](HLS.md).

Новый профиль входа: GOP до 4 секунд, сумма выбранных видео/аудиопакетов до 6 Мбит/с в каждой секундной корзине и в среднем. Превышение даёт `.rejected`/`needs_preparation`; подготовьте файл указанным выше скриптом на компьютере (VBV 2 Мбит). Если свободно менее 40 MiB в HLS tmpfs, `.ready.mp4` ждёт (`buffer_busy`): не загружайте повторно.

## Optional-режимы адресов

В `/etc/player/player.conf`: `INTERFACE_MODES=0` — видео везде; `INTERFACE_MODES=1` и `STILL_INTERFACES='eth0'` — картинка по адресам выбранного NIC, видео по остальным, включая Wi-Fi. Реальные имена уточните через `ip link`. Подхватывается автоматически; адрес назначения, а не IP клиента/Host определяет режим. Это не firewall. На статичном адресе оба HLS-пути дают 404.

JPEG: SFTP `/data/still/image.part` → `/data/still/image.jpg`, затем обновить страницу. USB NIC подключайте до питания; late cable не равен USB hotplug. Инструкция и dual-QEMU: [ETHERNET](ETHERNET.md).

## Эмулятор

Нужен `qemu-system-aarch64`, а также `qemu-img`. По умолчанию запускается ARM `virt` с Cortex-A72/VirtIO: используется **тот же Pi kernel и тот же raw**, но быстрая виртуальная сеть. Запуск из исходников:

```bash
scripts/run-qemu.sh --reset
python3 scripts/upload.py ready.mp4 --host 127.0.0.1 --port 2222 --key dist/admin_ed25519
```

QEMU занимает свой терминал; upload и smoke выполняются во втором терминале, пока VM работает.

Страница: `http://127.0.0.1:8080`, SSH/SFTP: `127.0.0.1:2222`. Пробросы слушают только localhost. QEMU использует отдельный qcow2 overlay с виртуальной ёмкостью 512 MiB (для SD модели нужен размер степени двойки); **его не записывают на карту**, raw-образ остаётся меньше 512 MB. `--reset` удаляет тестовые данные VM; перед ним остановите QEMU. Для обычного продолжения без сброса запускайте без флага. После смены raw скрипт требует reset и проверяет совпадение базового хеша.

Для проверки загрузки модели платы: `scripts/run-qemu.sh --raspi4 --reset` (дополнительно fdtput/fdtget из device-tree-compiler). В QEMU 11.1.3 её USB-сеть в нашей проверке даёт около 0.87 Мбит/с: это ниже битрейта demo.mp4 и вызывает буферизацию. Этот режим проверяет загрузку/сервисы; для просмотра видео используйте стандартный VirtIO-режим. Он не подтверждает физический Wi-Fi, Ethernet или firmware boot chain Pi.

## Администрирование

Пароль root отключён. Административный доступ: `ssh -i dist/admin_ed25519 root@192.168.50.1`. Ключ и credentials приватные; не публикуйте их. Настройки AP: `/etc/player/player.conf`, перезапуск: `/etc/init.d/S45accesspoint restart` (Wi-Fi при этом отключится).

Проверка: `cat /run/player/status.json`, `cat /run/player/ffmpeg.log`, `cat /run/player/ap.log`, `df -h /data`. Данные и активный ролик сохраняются после перезагрузки; HLS и рабочие логи хранятся в RAM. Для выключения: `poweroff` через административный SSH.

Место для видео — остаток системного раздела. При замене старый и новый ролики временно занимают место одновременно. Свободное место проверьте перед передачей; универсальной поддержки произвольного размера нет. При очень большом битрейте/длинном GOP подготовьте ролик указанным скриптом.

Перед сдачей: проверить Wi-Fi, SFTP, звук, циклическое воспроизведение, замену файла, Ethernet, перезагрузку и размер образа. Эмулятор не подтверждает работу физического Wi-Fi.
