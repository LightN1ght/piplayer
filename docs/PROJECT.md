# PiPlayer: описание проекта

PiPlayer превращает Raspberry Pi 4 Model B в автономный сетевой видеоплеер. После включения устройство поднимает Wi-Fi AP, принимает файл по SSH/SFTP и отдаёт общий непрерывный циклический HLS-поток на HTTP-порту 8080. Интернет для просмотра не требуется.

Дедлайн базовой версии: **6 ноября 2026 года, 16:00 МСК**. Этот документ описывает объём первой версии; устройство считается принятым только после проверок ниже.

## Пользовательский сценарий

1. Записать raw-образ на microSD и включить Pi.
2. Подключиться к AP по данным из приватного `credentials.json` либо найти DHCP-адрес устройства в Ethernet-сети.
3. Открыть `http://192.168.50.1:8080` через AP или `http://<адрес-устройства>:8080` через Ethernet.
4. По SFTP загрузить `/data/incoming/<имя>.part`, после завершения передачи переименовать в `<имя>.ready.mp4`.
5. Сервис проверит файл и заменит активное видео. Браузеры получат одно общее поколение потока; пользователь нажмёт «Смотреть со звуком» для разрешения звука и запроса fullscreen.

Для внешней программы новая версия предоставляет `http://192.168.50.1:8080/stream.m3u8`; через Ethernet используется DHCP-адрес с тем же портом и путём. Это служебный HLS-плейлист одного активного ролика, не пользовательская очередь. См. [HLS](HLS.md).

Инструкция и команды: [QUICKSTART.md](QUICKSTART.md).

## Границы первой версии

| Требование | Реализация и критерий приёмки |
| --- | --- |
| Минимальный Linux для Pi 4 B | Buildroot, BusyBox init, без desktop и компилятора в образе; проверяется загрузкой на плате |
| Карта номиналом 512 MB | Raw-образ не больше 480 000 000 байт; это действующий программный предел, а не 470 MB. Дополнительно проверяется реальная ёмкость выбранной карты |
| AP после загрузки | hostapd + dnsmasq; клиент получает адрес и открывает плеер без Интернета |
| SSH/SFTP | `player` загружает файл, root доступен по индивидуальному ключу; приватные данные передаются отдельно |
| Общая непрерывная трансляция | Один FFmpeg читает активный файл по кругу; клиенты подключаются к одному HLS. Точная синхронизация кадров между клиентами не обещается |
| Звук | AAC передаётся в HLS; автоматический звук ограничен политиками браузера, поэтому предусмотрена кнопка |
| Чёрная страница и fullscreen | Видео вписано в площадь страницы на чёрном фоне; нативный fullscreen требует поддержки и действия пользователя |
| Доступ со всех адресов | nginx слушает `0.0.0.0:8080` и `[::]:8080`; достижимость проверяется по реально назначенным адресам |
| Первая версия формата | MP4 с H.264 8 bit yuv420p и AAC; ролик без аудиодорожки также допустим. Подготовка через FFmpeg на компьютере |

Разные режимы Ethernet исключены из обязательного базового сценария, но реализованы отдельно как opt-in по адресам интерфейсов (см. [ETHERNET](ETHERNET.md)). В базовую версию также не входят транскодирование произвольных форматов на Pi, веб-загрузка, индивидуальные сеансы просмотра и маршрутизация Интернета через AP.

Актуальная версия и протоколы проверок: [CURRENT_STATE](../agents/CURRENT_STATE.md), [VALIDATION](../agents/VALIDATION.md). Аппаратная приёмка базового образа не переносится автоматически на обновлённый raw.

## Что передать пользователю

Raw-образ, сжатую копию, SHA256SUMS, инструкцию, исходники и честный список пройденных/непройденных проверок. `credentials.json` и `admin_ed25519` передаются приватно. Архив исходников проекта не заменяет исходники и лицензии зависимостей; для их подготовки предусмотрен Buildroot `make legal-info`.

Карта дальнейшей работы: [ARCHITECTURE.md](ARCHITECTURE.md), [ROADMAP.md](../agents/ROADMAP.md), [TASKS.md](../agents/TASKS.md).

6 ноября пользователь дополнительно подтвердил SFTP-загрузку собственного ролика через Wi-Fi с Android, замену видео со звуком и 60 с одновременного просмотра ноутбук+телефон без остановок. Репозиторий исходников: [LightN1ght/piplayer](https://github.com/LightN1ght/piplayer), ветка main; результаты публикации в TASKS.

Новый профиль: GOP до 4 секунд и до 6 Мбит/с по реальным пакетам выбранных видео/аудиопотоков (секундные корзины и среднее). Подготовка на хосте: 2 Мбит/с, maxrate 3 Мбит/с, VBV 2 Мбит, GOP 2 секунды. Pi не транскодирует. При менее 40 MiB свободного места HLS tmpfs ready-файл ожидает ресурса без повторной загрузки.
