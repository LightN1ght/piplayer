# Решения и их причины

| Решение | Причина | Следствие / ограничение |
|---|---|---|
| Buildroot вместо удаления пакетов из полной ОС | Управляемый состав, кросс-сборка и небольшой userspace | На устройстве нет package manager/компилятора; обновления через сборку |
| Pi 4 B, ARM64, штатный bcm2711 kernel defconfig с отключением тяжёлых подсистем | Быстрый путь к поддержке реальной платы | Ядро не минимизировано до каждого драйвера; совместимость важнее нескольких МБ |
| Nginx + FFmpeg HLS | Общая временная шкала для зрителей, обычный браузер | HLS добавляет задержку; это имитация сетевой live-камеры, не USB/UVC/ONVIF |
| H.264/AAC без перекодирования на плате | Низкая CPU-нагрузка и компактная сборка | Другие кодеки готовятся на хосте через prepare-video.sh |
| Один активный файл | Ясный сценарий SFTP и дедлайн | Пользовательская очередь/выбор библиотеки вне MVP; служебный HLS m3u8 необходим |
| `.part` → `.ready.mp4` → проверка → atomic rename | Незавершённая/неподходящая загрузка не заменяет рабочий ролик | Во время замены нужны место под старый и новый файлы |
| Сегменты и логи в RAM | Избежать постоянных записей HLS на карту | Размер RAM-буфера ограничен; длинный GOP/очень высокий битрейт требуют подготовки |
| Отдельный пользователь player | FFmpeg не требует root; SFTP работает в /data | Администрирование системы отдельно через root SSH-key |
| Индивидуальные пароли и ключ администратора | Готовый образ без общего публичного пароля | Данные доступа передаются отдельными приватными файлами, не через Git/чат |
| Wi-Fi AP + DHCP, без NAT/интернет-шлюза | Устройство предназначено для локального просмотра | Клиент может обозначать Wi-Fi как сеть без Интернета |
| Сервер слушает все адреса | Прямое уточнение техадмина | Optional-режим выбирается destination IP; default видео везде, это не firewall |
| MBR PARTUUID для root | В QEMU и на плате разные номера MMC | Сигнатура MBR и cmdline проверяются в самом raw-образе |
| QEMU direct kernel boot + приватный DT | Обойти отсутствующие/отличающиеся устройства модели | Не проверяет реальную firmware boot chain, Wi-Fi и радио; это отдельная приёмка платы |
| Raw <=480000000 байт | Запас относительно карты с маркировкой 512 MB | Проверяется raw и разметка, а не размер xz |
| Постоянный build cache вне /tmp | Перезапуск ноутбука не должен уничтожать результаты | Путь без пробелов; загрузки дополнительно сохраняются в проекте |


## Дополнения 6 ноября

- Постоянный `/stream.m3u8` нужен внешней HLS-программе без JS. Shell/awk publisher добавляет общую media sequence и discontinuity, удерживает старые сегменты; браузер продолжает использовать private generation URL. Очереди пользовательских роликов нет.
- Ограничения GOP 4 секунды и 6 Мбит/с по пакетам защищают tmpfs 96 MiB. Helper готовит ролик на хосте (VBV 2 Мбит); Pi только копирует потоки. При свободном tmpfs <40 MiB ready-файл ждёт, а старое видео продолжается.
- Статичный режим интерфейсов opt-in: `INTERFACE_MODES=0` по умолчанию. Привязка по фактическим именам и destination IPv4/IPv6, не по MAC, клиенту или Host. На статичном адресе HLS даёт 404; SSH/SFTP остаются доступны.
- Аппаратный baseline и обновлённый HLS/Ethernet raw учитываются раздельно. Новый raw прошёл хостовые и чистые ARM VM проверки с внешними FFmpeg/mpv, но это не заменяет аппаратную проверку обновления. Точная программа организатора неизвестна.

Практические инструкции: [HLS](HLS.md), [ETHERNET](ETHERNET.md). Актуальный статус: [CURRENT_STATE](CURRENT_STATE.md).
