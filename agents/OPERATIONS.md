# Работа и восстановление среды

## Обычная разработка

Сначала прочитать CURRENT_STATE и TASKS. Источники лежат в корне проекта, staged-копия для Buildroot — в `<work>/project`, результат — `<work>/output/images`. По умолчанию `<work>` равен `$HOME/.cache/piplayer-build`.

```bash
scripts/build.sh
scripts/run-qemu.sh --reset
python3 -u scripts/smoke.py --reboot
```

`--reset` стирает только тестовое состояние VM и требует, чтобы VM была остановлена. Без него запуск отвергает overlay от другого raw-хеша. Запущенная VM не должна иметь изменяемый backing image: сначала остановить её, затем пересобрать/упаковать raw.

Для сборки без перезаписи dist: `PIPLAYER_SKIP_PACKAGE=1 scripts/build.sh`. Это полезно, пока работает VM на старом образе. Последующая упаковка — `scripts/package.sh <work>/output/images`, после остановки VM и достаточных проверок. Для обновления только исходников/документов без изменения backing image: `scripts/package-source.sh`.

## Логи и проверки

| Что | Где / команда |
|---|---|
| Полная сборка | `.build/build.log`, краткий запуск `.build/full-build-run.log` |
| QEMU boot | `.build/qemu.log` |
| Проверка сервиса на хосте | `python3 -m unittest discover -s tests -v` |
| Проверка файла образа | `python3 scripts/check-image.py dist/piplayer-rpi4.img` |
| Сеть/сервисы устройства | `ssh -p 2222 -i .local/admin_ed25519 root@127.0.0.1` (QEMU) |
| Runtime устройства | `/run/player/status.json`, `ffmpeg.log`, `ap.log` |
| Место | `df -h /data` |

Прямой HLS для внешней программы: `/stream.m3u8`; HTTP 200 следует дополнить настоящим декодированием, циклом и сменой ролика. Двухсетевой QEMU и `smoke-interface-modes.py` описаны в [ETHERNET](../docs/ETHERNET.md), `smoke-direct-hls.py` — в [HLS](../docs/HLS.md). Эти сценарии заменяют видео и могут перезагружать тестовое устройство. Не запускать их параллельно на одной VM.

SSH не должен отключать проверку ключа хоста. После нового чистого QEMU диска его ключ изменится; launcher --reset удаляет только прежнюю локальную запись тестового адреса/порта из проектного known_hosts.

## После выключения ноутбука

1. Не повторять команды со старыми PID/exec ID. Проверить существование work/output и свежесть артефактов.
2. Если пропал только /tmp, использовать постоянные `.build/downloads`, `.build/tools` и dist. Если исчез build cache, потребуется новая компиляция, но архивы повторно скачивать обычно не надо.
3. Проверить хеш raw и соответствие исходников. Кандидат, offline исправленный через debugfs, не называть подтверждённой полной сборкой.
4. Восстановить источник правды: финальный build.sh → check-image → чистый QEMU → smoke → физическая плата.

## Остановка

В интерактивном QEMU: Ctrl+A, C, затем `quit`. Для автоматизации есть локальный Unix QMP-сокет `.build/qemu.qmp`; сначала capabilities, затем quit. Это выключает VM как эмулятор, поэтому для проверки корректного завершения гостя сначала используйте `poweroff` внутри гостя.

При просьбе пользователя остановиться: остановить свои тестовые VM/сервисы и активную сборку, записать точку продолжения в CURRENT_STATE, не удалять кэш и артефакты. Запись на SD и любые реальные сетевые изменения на хосте не входят в остановку/возобновление разработки.
