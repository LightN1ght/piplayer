# Проверки PiPlayer

Обновлено: 6 ноября 2026. Проверки хоста, диагностической VM, финального raw и платы учитываются отдельно.

## Подтверждено на хосте x86_64

- `python3 -m unittest discover -s tests -v`: PASS, один интеграционный сценарий, последний прогон 31.37 секунды, `.build/host-tests.log`.
- Настоящие FFmpeg/ffprobe: H.264 + AAC; новые сегменты появляются после окончания исходного ролика, плейлист продолжает продвигаться.
- `.part` не активируется; неверный `.ready.mp4` отклоняется и не прерывает прежний поток.
- Замена файла создаёт новое поколение HLS; SIGKILL и SIGSTOP FFmpeg приводят к восстановлению. Watchdog теста 4 секунды, штатное значение 60.
- Проверка синтаксиса JS, Python и shell-скриптов: PASS.
- Встроенный браузер: HLS реально воспроизводится (640x360, readyState=4, время растёт за пределами длительности восьмисекундного файла). Кнопка включает звук (`muted=false`, `paused=false`). Снимок: `.build/player-preview.jpg`.
- Fullscreen API во встроенном браузере недоступен; нативный fullscreen нужно проверить в обычном браузере. Заполнение всей площади страницы подтверждено визуально.

- Штатный ARM watchdog с timeout=60: после SIGSTOP состояние stream_stalled через 60.5 с, новое buffering через 68.6 с, playing через 70.6 с. Лог `.build/freeze-test.log`, ARM SIGSTOP WATCHDOG PASS.

### Граница браузерной проверки

При длительном фоновом прогоне IAB с native HLS наблюдалась остановка currentTime около 13.9 с при paused=false и readyState=2; часть диапазонов buffered имела разрывы. Причина не доказана. Независимая проверка пяти TS-сегментов не выявила разрывов DTS: H.264 шаг 0.04 с, AAC 0.021333–0.021334 с, межсегментная погрешность AAC не более микросекунды. Это ограниченная выборка, не доказательство для любых файлов.

Приоритет изменён на hls.js при наличии MSE, native HLS оставлен fallback; исправлена повторная кнопка после отклонённого play(). Затем пользователь подтвердил те же остановки в Helium каждые ~5 секунд. Измерение показало ограничение USB NIC raspi4b: 0.864–0.889 Мбит/с при demo ~1.1 Мбит/с. Двухсекундный сегмент передавался 2.4–2.8 с. После перехода на ARM virt/VirtIO скорость103–130Мбит/с, а пользователь после Ctrl+Shift+R подтвердил30–60с плавного воспроизведения со звуком. Поэтому предыдущие симптомы нельзя приписывать ошибке FFmpeg или фоновому WebView без оговорки о сети.
